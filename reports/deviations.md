# Deviations from the preregistration and exploratory additions

Every change relative to [preregistration.md](preregistration.md) is listed here with its date and reason, as the preregistration requires. Analyses that were not preregistered are labelled **exploratory** here and everywhere else they appear.

| Date | Item | Preregistered | What was done | Reason |
|---|---|---|---|---|
| 2026-10-31 | Baseline sample size | B1, B2 and B3 run on the synthetic test set | B1–B3 run on a fixed subset: the first `baseline_per_cell` = 20 samples per family in each of the 12 cells, 3,120 samples. H1/H2 are paired on this subset. The method runs on the full test set. | B1 fits all 13 families with multi-start refinement (61 refinement runs per cloud). On the full 39k-sample set that would take more than 10 GPU hours on the 8 GB laptop GPU. |
| 2026-10-31 | Ablation budget | "3 seeds per ablation" | Each ablation is trained with a shorter, shared budget (12k steps / 60 min). It is compared against **A0**, the unchanged method retrained with the same short budget (configs `ablation_A*.yaml`). The number of seeds per ablation is reported with the results. | A matched-budget reference isolates the effect of each ablation from the effect of training length. The total GPU budget is limited. |
| 2026-10-31 | Training length | 100k steps | Steps are set from the measured speed (≈0.23 s/step at batch 512) and capped at 110 wall-clock minutes per seed. The steps actually completed are recorded in `results/<run>/train/summary.json`. | 8 GB laptop GPU budget. |
| 2026-10-31 | Counting-task text (R4) | Replication recipe text (FineWeb) | Text comes from `NeelNanda/pile-10k` documents, whitespace-normalised and wrapped with `textwrap.fill(width=150)`. | The corpus was already cached locally. The manifold is defined by line position, not corpus content. |
| 2026-10-31 | Bhalla et al. value ranges (R6–R8) | Templates from their Table 1 | The paper gives templates and sample sizes but not value ranges. We use: years 1801–1999 (n=199); 150 Fahrenheit values from −20 to 129; ages 1–99; 900 hex colours on an HLS grid (36 hues × 5 saturations × 5 lightnesses). The years template is "The date is year {Y}". | The paper does not specify the ranges. We chose ranges that match its sample sizes. |
| 2026-10-31 | Layer convention | "layer L" | `output_hidden_states[L]` in Hugging Face, i.e. the residual stream after L blocks. Models are truncated to L+1 blocks so index L is never the norm-applied final state. | The papers do not state an unambiguous index convention. |
| 2026-10-31 | **Exploratory** datasets | — | Added: R4b (Pythia-410m counting, layer 6), R5c ("It's {time} on {day}", Llama layer 19), R3 with n=20 features, class-mean versions of R5a/R5b (`*_means`), and controls `C3_grokking_WE_memorised` and `C3_tms_dense` (no preregistered label). | These are cheap extra views of the same phenomena. They are excluded from H3 and labelled exploratory. |
| 2026-10-31 | B2 classifier family fit | "B1's fit for the predicted family" | B2 reuses B1's per-family fits for the family it predicts, without recomputation. Correction (2026-11-01): it is not quite identical to B1's choice. For clusters and polytope, B2 takes the candidate (k or template) with the lowest objective, whereas B1 chooses among them by geometric AIC (`eval/synth_eval.py`). | Saves compute. |
| 2026-10-31 | Crash and resume of `main_s0` | One uninterrupted training run | At step 19000 (89.5 min), cuSOLVER's batched `eigh` failed to converge on a rank-deficient covariance: a noise-free shape embedded in R^256 has 253 repeated zero eigenvalues. The last checkpoint (step 9999) held only model weights. Training resumed from it with a fresh AdamW state and a 500-step learning-rate re-warmup, keeping the original schedule and the 110-minute total budget. Steps 0–9999 of the training curve were recovered from the log (`logs/main_s0_train_stdout_crashed_step19000.txt`, published in the [Hugging Face model repository](https://huggingface.co/BurnyCoder/neurogeom-shape-fitter-main-s0/tree/main/logs)). Steps 10000–19000 of the crashed run were discarded. | The fix is a float64 CPU fallback for `eigh`, full-state checkpoints every 2000 steps, and non-fatal generation errors. Restarting from scratch would have cost another 90 GPU minutes. |
| 2026-10-31 | Memory-efficient nearest-point distance (implementation only) | — | The first `main_s0` synthetic evaluation stalled at 21,548 of 39,000 clouds. Refining 3 candidate surfaces for 512 clouds of 256 points against 1,600 shape samples kept several (B, N, M) distance matrices for autograd (> 8 GB), and Windows paged GPU memory to system RAM. `nearest_dist` now finds the nearest index without autograd, in chunks, and differentiates only the gathered pair (the pytorch3d `knn_points` + `knn_gather` split). The value and gradient are the same as a min over the full matrix up to ties (unit test). Peak VRAM for that batch fell to 0.7 GiB. The evaluation was restarted from the first cloud, so every reported synthetic number uses the new code. `main_s0` was trained with the old implementation of the same function. | Without it the evaluation of the two largest N-bins could not finish on 8 GB. |
| 2026-10-31 | Order of work: evaluation code | Core functionality (including evaluation) pushed before the first training run | The preregistration (05:31) and the core geometry, model, training loop and detailed README (PR #1 and #2, merged 05:48 and 06:00) were pushed before `main_s0` training started at 06:00. The evaluation, baselines and real-data code (PR #3) was pushed at 06:43, while `main_s0` was training but before any evaluation result existed. The analysis plan it implements was fixed in the preregistration at 05:31. | The evaluation code was written while the GPU trained. No result could influence it. |
| 2026-10-31 | Order of work: trained controls and baselines | Stages: one model with the controls and baselines that need no training, published → trained control models → trained baseline models → ablation models → more models / controls / baselines / ablations → seed and hyperparameter sweeps. Each stage is published (paper, results, reports, README, website, Hugging Face) before the next starts. | This order was set after the first evaluation had started. Three trained components were evaluated in the same run as `main_s0`: B2, a gradient-boosting classifier trained on synthetic features, and two trained control checkpoints, `C3_grokking_WE_memorised` and `C3_tms_dense`. They are published with the first model, as the author chose, not as later stages. The untrained baselines (B1, B3) and controls (C1, C2, the random-init C3) belong to the first stage by design. Ablations (`bash scripts/sweep.sh ablations`) and seed and hyperparameter sweeps (`bash scripts/sweep.sh sensitivity`) are postponed at the author's request. | These results already existed, and holding them back for later snapshots would misrepresent when they were obtained. |
| 2026-10-31 | **Post hoc:** counting extraction skips sequence position 0 | Mean activation per character count over all tokens | The first Pythia counting cloud (R4b, exploratory) had its count-1 mean at 50× the median distance from the centre. Pythia's tokenizer adds no BOS token, so each document's first token, an attention sink with massive activations (Sun et al. 2024, arXiv:2402.17762; Xiao et al. 2024, arXiv:2309.17453), fell into the count bin of its own length. Position 0 is now skipped for every model. Llama's position 0 is BOS and was already excluded, so the preregistered R4 and C3 counting clouds are unchanged. R4b was re-extracted and re-evaluated alone (`--set "eval.real_only=[R4b_pythia_counting]"`). It changed from clusters (one outlier against the rest) to ringing. Because H4 averages the matched-Gaussian blob rate over all real datasets, that mean changed from 82% to 86%; H4 passes both ways. The superseded cloud and results are kept in `data_cache/real_superseded/`. | A known extraction artifact, found by inspecting outliers after seeing the fit. It is post hoc, so it is flagged here. It affects only an exploratory dataset that H3 does not use. |
